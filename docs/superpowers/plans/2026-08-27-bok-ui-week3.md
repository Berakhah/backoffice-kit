# bok-ui v0.1 — Implementation Plan (Week 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `bok-ui` v0.1.0 to npm — the token layer whole, nine components, and a Storybook on GitHub Pages with axe passing — before `agent-perimeter`'s week 4 needs it.

**Architecture:** Tokens land whole; components land lazily. `bok-ui` publishes to npm, so adding a component later is a minor version bump while changing a token later is a breaking visual change across four repos. That asymmetry decides the split: the OKLCH ramp, the semantic scales, the density *mechanism*, the a11y contract and the print sheet are complete in v0.1; four components and all chart primitives defer to the phase that first demands them.

**Tech Stack:** TypeScript (strict), React 19, Vite (library mode), Vitest + Testing Library, Storybook 8, `@storybook/addon-a11y` + `axe-core`, npm trusted publishing (OIDC).

**Spec:** `docs/superpowers/specs/2026-08-27-backoffice-kit-design.md` §8
**Interface contract:** `docs/INTERFACE-CONTRACT.md` **v0.2** §6 — the component surface the four consumer repos check against.
**Companion plan:** `2026-08-27-bok-core-week0.md`. `RailPayload` is produced by `bok_core.provenance.render.to_rail()`; this package consumes that exact JSON shape.

## Global Constraints

- **TypeScript strict.** No `any` without a comment justifying it on the same line.
- **Light mode is primary.** Dark exists and is excellent; light is what you design first and what screenshots use.
- **Severity and provenance state are never encoded in colour alone.** Every semantic colour ships a glyph *and* a text label. Two target markets are regulated for accessibility.
- **Tabular numerals wherever a number appears.** A column of figures that shifts as it updates is the fastest way to look amateur to a controller.
- **Self-hosted fonts only.** No Google Fonts CDN call — a privacy and offline-demo liability.
- **`prefers-reduced-motion` disables all motion.** Not reduces — disables.
- **axe-core: zero serious or critical violations**, enforced in CI.
- **Reject three looks explicitly:** warm-cream + serif + terracotta; near-black + single acid accent; broadsheet with hairlines and zero radius. If a screen could drop into any of the four products unchanged and still look right, it is too generic.
- Every exported symbol must appear in `docs/INTERFACE-CONTRACT.md` §6.

The `./print.css` export exists because its first consumer is `agent-perimeter`'s
`report/html.py` — server-rendered Python HTML that never imports React.

**R1 — five problems in this manifest, each of which stops the build or ships a broken package.**

1. **`storybook` itself was not a dependency.** `@storybook/react-vite` and `addon-a11y` were
   listed; the CLI that `storybook dev` and `storybook build` invoke was not. `npm run storybook`
   fails on a clean install.
2. **`@vitejs/plugin-react` was missing**, so JSX does not compile in either the build or the tests.
3. **`density.css` has no export.** The token layer is declared to "land whole", and a consumer
   cannot import the half of it carrying the density mechanism. Add
   `"./density.css": "./dist/density.css"`, or `@import` it from `theme.css` — pick one and say
   which, because a consumer who imports `theme.css` and gets no `--bok-density-*` variables gets a
   silently collapsed layout rather than an error.
4. **Vite library mode does not emit those files.** By default it bundles all CSS into a single
   `style.css`, so `./dist/theme.css` and `./dist/print.css` do not exist and every CSS export in
   this manifest 404s at install time. That is what `vite.config.ts` is for — it is listed under
   **Files** and no step writes it. See Step 3a.
5. **`@storybook/test-runner`, `axe-playwright` and `@playwright/test` are new in R1.** They are how
   axe actually runs against rendered colour; Task 11 explains why the jsdom path cannot.

Verify before pinning: `@storybook/react-vite@^8.2` predates React 19 GA, and `vitest-axe@0.1.0`
was published against vitest 0.x/1.x. Either may need a newer major. Run `npm ls` after install and
resolve peer warnings rather than silencing them — a peer warning here is a component library
shipping against a React it was never tested on.

```ts
// src/tokens/tokens.test.ts
import { readFileSync } from "node:fs";
import { describe, expect, it } from "vitest";
import { PROVENANCE_STATE, SEVERITY } from "../semantics";

const theme = readFileSync(new URL("./theme.css", import.meta.url), "utf8");
const density = readFileSync(new URL("./density.css", import.meta.url), "utf8");

describe("token layer", () => {
  it("defines a twelve-step warm-graphite ramp in OKLCH", () => {
    for (let i = 1; i <= 12; i++) expect(theme).toContain(`--bok-neutral-${i}:`);
    expect(theme).toContain("oklch(0.985 0.004 85)"); // paper
    expect(theme).toContain("oklch(0.22 0.012 85)"); // ink
  });

  it("defines one accent per product from a shared chroma", () => {
    expect(theme).toContain("oklch(0.72 0.16 68)"); // agent-perimeter amber
    expect(theme).toContain("oklch(0.58 0.11 158)"); // ledger-sense green
    expect(theme).toContain("oklch(0.55 0.14 268)"); // selector-drift indigo
    expect(theme).toContain("oklch(0.52 0.10 232)"); // ground-truth slate-blue
  });

  it("never encodes a semantic state in colour alone", () => {
    for (const entry of [...Object.values(SEVERITY), ...Object.values(PROVENANCE_STATE)]) {
      expect(entry.glyph.length).toBeGreaterThan(0);
      expect(entry.label.length).toBeGreaterThan(0);
      expect(entry.token).toMatch(/^--bok-/);
    }
  });

  it("ships the density mechanism with comfortable and compact, defaulting to compact", () => {
    expect(density).toContain('[data-density="comfortable"]');
    expect(density).toContain('[data-density="compact"]');
    expect(density).toContain("--bok-density-row");
    // `dense` is deferred to week 5 -- the MECHANISM ships, the third mode does not.
    expect(density).not.toContain('[data-density="dense"]');
    expect(density).toMatch(/:root[^{]*\{[^}]*--bok-density-row/);
  });

  it("uses tabular numerals wherever numbers render", () => {
    expect(theme).toContain("font-variant-numeric: tabular-nums");
  });

  it("re-anchors every semantic colour for dark, not just paper and ink", () => {
    // R1: the dark block swapped two variables and left eleven at their light-mode
    // lightness, so every badge, accent and provenance state failed contrast on dark --
    // while DoD item 3 claims axe passes in dark.
    const dark = theme.slice(theme.indexOf('[data-theme="dark"]'));
    for (const t of ["critical", "high", "medium", "low", "info",
                     "verified", "modelled", "unverified"]) {
      expect(dark).toContain(`--bok-${t}:`);
    }
  });

  it("ships a text-weight variant of every semantic colour", () => {
    // Borders and fills need 3:1; text and glyphs need 4.5:1. One value cannot serve both
    // without either failing AA or draining the colour out of the badge.
    for (const t of ["critical", "high", "medium", "low", "info",
                     "verified", "modelled", "unverified"]) {
      expect(theme).toContain(`--bok-${t}-ink:`);
    }
  });

  it("self-hosts fonts and never calls a CDN", () => {
    expect(theme).toContain("@font-face");
    expect(theme).not.toContain("fonts.googleapis.com");
    expect(theme).not.toContain("fonts.gstatic.com");
  });

  it("disables motion under prefers-reduced-motion", () => {
    expect(theme).toContain("@media (prefers-reduced-motion: reduce)");
    expect(theme).toContain("animation-duration: 0.01ms");
  });
});
```

```ts
// src/types.ts
// Mirrors bok_core.provenance.render.RailPayload. Field names are snake_case because
// they cross a Python boundary; renaming them here would hide a drift rather than
// surface it.

export type Method = "DETERMINISTIC" | "MODEL" | "HUMAN" | "DERIVED";
export type Derivation = "SCHEMA" | "DESCRIPTION" | "PROBE" | "ARTIFACT";
export type CalibrationState = "UNCALIBRATED" | "CALIBRATED";

export interface Calibration {
  readonly state: CalibrationState;
  readonly basis: string;
  readonly curve_id: string | null;
  readonly n: number | null;
}

export interface RailNode {
  /** A Decimal arrives as a string. Never coerce it to a number. */
  readonly value: string | number | boolean | null;
  readonly method: Method;
  readonly derivation: Derivation | null;
  readonly source_kind: string;
  readonly source: Readonly<Record<string, unknown>>;
  readonly confidence: number | null;
  readonly calibration_state: CalibrationState | null;
  readonly calibration_basis: string | null;
  readonly renders_as_fact: boolean;
  readonly observed_at: string;
  readonly caveat: string | null;
  readonly parents: readonly RailNode[];
}

export interface RailPayload {
  readonly root: RailNode;
  readonly depth: number;
  readonly inherited_caveats: readonly string[];
}

/** Which provenance colour, glyph and label a node renders with.
 *
 *  R1: the plan contradicted itself here. This function sends the fixture's DERIVED root
 *  to "modelled" -- it is neither DETERMINISTIC nor HUMAN, and pre-revision bok-core
 *  returned renders_as_fact=true for it -- while Task 5's first test asserts "verified".
 *  One of the two had to fail on the very first run.
 *
 *  Resolved in favour of bok-core's I7, which R1 also added: a DERIVED claim is only as
 *  verified as its weakest ancestor. The three states are therefore:
 *
 *    verified    -- DETERMINISTIC or HUMAN, or DERIVED only from such claims
 *    modelled    -- involves a MODEL claim whose confidence IS calibrated
 *    unverified  -- involves a MODEL claim that is not calibrated
 *
 *  which is the distinction 00 B10 exists to force, and it now reads identically on both
 *  sides of the Python boundary instead of being re-derived, differently, in TypeScript.
 */
export function provenanceStateOf(node: RailNode): "verified" | "modelled" | "unverified" {
  if (!node.renders_as_fact) return "unverified";
  return involvesModel(node) ? "modelled" : "verified";
}

function involvesModel(node: RailNode, seen = new Set<RailNode>()): boolean {
  if (seen.has(node)) return false;      // chains are DAGs; never re-walk a shared parent
  seen.add(node);
  if (node.method === "MODEL") return true;
  return node.parents.some((p) => involvesModel(p, seen));
}
```

```ts
import { useCallback, useRef, useState, type KeyboardEvent } from "react";

export interface RovingOptions {
  count: number;
  onActivate?: (index: number) => void;
  /** Extra single-key actions, keyed lower-case. ledger-sense binds E (edit), R (reject).
   *
   *  R1: the hook exposed only onActivate, and ledger-sense's review queue needs
   *  J/K/Enter/E/R to clear fifty exceptions without a mouse. Serving that queue is the
   *  stated reason this primitive is separate from the table at all. */
  actions?: Record<string, (index: number) => void>;
}

/** One tab stop, arrow/J/K/Home/End movement, Enter to activate.
 *  Shared by FindingsTable and by ledger-sense's review queue -- a queue is not a
 *  table, but the keyboard contract is identical. */
export function useRovingTabIndex({ count, onActivate, actions }: RovingOptions) {
  const [activeIndex, setActiveIndex] = useState(0);
  const refs = useRef<(HTMLElement | null)[]>([]);

  const focusAt = useCallback((next: number) => {
    const clamped = Math.max(0, Math.min(count - 1, next));
    setActiveIndex(clamped);
    refs.current[clamped]?.focus();
  }, [count]);

  const onKeyDown = useCallback(
    (e: KeyboardEvent<HTMLElement>) => {
      // R1: J/K were matched case-sensitively while the spec writes them as capitals,
      // and the handler claimed those keys unconditionally -- so typing "j" into a filter
      // input inside the container moved the selection instead.
      const t = e.target as HTMLElement;
      if (t.isContentEditable || ["INPUT", "TEXTAREA", "SELECT"].includes(t.tagName)) return;

      const k = e.key.length === 1 ? e.key.toLowerCase() : e.key;
      const moves: Record<string, number> = {
        ArrowDown: activeIndex + 1, j: activeIndex + 1,
        ArrowUp: activeIndex - 1, k: activeIndex - 1,
        PageDown: activeIndex + 10, PageUp: activeIndex - 10,
        Home: 0, End: count - 1,
      };
      if (k in moves) {
        e.preventDefault();
        focusAt(moves[k] as number);
        return;
      }
      if (k === "Enter") {
        e.preventDefault();
        onActivate?.(activeIndex);
        return;
      }
      const action = actions?.[k];
      if (action) {
        e.preventDefault();
        action(activeIndex);
      }
    },
    [activeIndex, count, focusAt, onActivate, actions],
  );

  return {
    activeIndex,
    setActiveIndex: focusAt,
    containerProps: { onKeyDown },
    itemProps: (index: number) => ({
      tabIndex: index === activeIndex ? 0 : -1,
      ref: (el: HTMLElement | null) => {
        refs.current[index] = el;
      },
      onFocus: () => setActiveIndex(index),
    }),
  };
}
```

```tsx
  readonly label: string;
}

export interface FindingRow {
  id: string;
  severity: SeverityKey;
  cells: Record<string, string>;
}

// R1: CSV FORMULA INJECTION. A cell beginning =, +, -, @, tab or CR is executed as a
// formula when the file is opened in Excel or Sheets. Every string in a FindingsTable
// originates in scanned material -- an MCP tool description, a DOM node, a vendor PDF --
// so this is attacker-controlled input, exported by a security product, to a controller
// who opens it in Excel. Prefixing with an apostrophe is the standard neutralisation and
// Excel does not render it.
const DANGEROUS = /^[=+\-@\t\r]/;
const q = (v: string) => `"${(DANGEROUS.test(v) ? `'${v}` : v).replace(/"/g, '""')}"`;

export function toCsv(rows: readonly FindingRow[], columns: readonly FindingColumn[]): string {
  const header = ["id", "severity", ...columns.map((c) => c.label)].map(q).join(",");
  const body = rows.map((r) =>
    [r.id, r.severity, ...columns.map((c) => r.cells[c.key] ?? "")].map(q).join(","),
  );
  // R1: CRLF per RFC 4180, plus a UTF-8 BOM -- without it Excel on Windows renders any
  // non-ASCII in a vendor name or an address as mojibake, on a deliverable whose entire
  // audience is Excel on Windows.
  return "\uFEFF" + [header, ...body].join("\r\n") + "\r\n";
}

export function toJson(rows: readonly FindingRow[]): string {
  return JSON.stringify(rows, null, 2);
}

export interface FindingsTableProps {
  rows: readonly FindingRow[];
  columns: readonly FindingColumn[];
  onRowActivate?: (row: FindingRow) => void;
  rowHeight?: number;
}

export function FindingsTable({
  rows, columns, onRowActivate, rowHeight = 32,
}: FindingsTableProps) {
  const [scrollTop, setScrollTop] = useState(0);
  const [widths, setWidths] = useState<Record<string, number>>({});
  const viewportRef = useRef<HTMLDivElement>(null);
  const viewportHeight = 640;

  // consumer needs variable row heights -- none does before week 13.
  const overscan = 6;
  const start = Math.max(0, Math.floor(scrollTop / rowHeight) - overscan);
  const end = Math.min(rows.length, start + Math.ceil(viewportHeight / rowHeight) + overscan * 2);
  const visible = useMemo(() => rows.slice(start, end), [rows, start, end]);

  // R1: count was visible.length and the index addressed the WINDOW. It now addresses
  // the dataset, and the window follows the active row -- the only arrangement in which
  // "virtualised" and "keyboard-navigable" are simultaneously true.

    count: rows.length,
    onActivate: (i) => {
      const row = rows[i];
      if (row) onRowActivate?.(row);
    },

    const top = roving.activeIndex * rowHeight;
    const el = viewportRef.current;
    if (!el) return;
    if (top < el.scrollTop) el.scrollTop = top;
    else if (top + rowHeight > el.scrollTop + viewportHeight)

    <div
```

```ts
import type { ReactNode } from "react";

/** A range in whatever coordinate system this adapter's content uses. */
export interface HighlightRange {
  label?: string;
}

/** The seam that lets one pane serve three content types.
 *  v0.1 ships the text/code adapter. The DOM adapter (node paths) lands in week 13
 *  with selector-drift; the document adapter (page + bbox) in week 5 with
 *  ledger-sense. Designing the seam now is what keeps that a new file rather than
 *  a rewrite of the pane. */
export interface ContentAdapter<TContent, TRange extends HighlightRange> {
  readonly kind: string;
  render(content: TContent, ranges: readonly TRange[]): ReactNode;
}

export interface TextRange extends HighlightRange {
  start: number;
  end: number;
}

export const textAdapter: ContentAdapter<string, TextRange> = {
  kind: "text",
  render(content, ranges) {
    const sorted = [...ranges]
      .map((r) => ({
        ...r,
        start: Math.max(0, Math.min(content.length, r.start)),
        end: Math.max(0, Math.min(content.length, r.end)),
      }))
      .filter((r) => r.end > r.start)
      .sort((a, b) => a.start - b.start);

    const out: ReactNode[] = [];
    let cursor = 0;
    sorted.forEach((r, i) => {
      // R1: overlapping ranges DUPLICATED text. With r.start < cursor the leading slice
      // was empty and the mark re-emitted characters already written, so two findings
      // highlighting the same evidence -- the normal case, not an edge case -- rendered
      // the overlap twice, and the excerpt no longer matched the source.
      const start = Math.max(r.start, cursor);
      if (start >= r.end) return;
      if (start > cursor) out.push(content.slice(cursor, start));
      out.push(
        <mark key={i} aria-label={r.label ?? "highlighted evidence"}>
          {content.slice(start, r.end)}
        </mark>,
      );
      cursor = r.end;
    });
    if (cursor < content.length) out.push(content.slice(cursor));
    return out;
  },
};
```

> ### R1 — the accessibility strategy in this task cannot test the requirement it exists for
>
> `vitest-axe` runs inside **jsdom**, which has no layout engine and computes no colours. axe's
> `color-contrast` rule detects this and returns *incomplete* rather than *pass* — it is skipped,
> silently. So the sweep below, cited by the definition of done as its evidence for *"every
> component in light, dark and all densities, with axe passing"*, produces 36 assertions that never
> look at a single colour.
>
> That matters more here than it usually would, because R1 found that three of the five severity
> colours fail AA as text on paper and that dark mode re-anchored nothing (Task 2). Those are
> exactly the violations this gate exists to catch, in two markets regulated for accessibility, and
> it could not have caught any of them.
>
> The CSS is also never loaded in the Vitest environment, so `<div data-theme="dark">` selects
> nothing — the theme dimension of the matrix is inert as well as blind.
>
> **Keep the jsdom sweep.** It catches structure, roles, names and ARIA, which is real value, and
> it is fast. **Add a real-browser gate and make that the DoD evidence:**
>

> // .storybook/test-runner.ts -- every story, headless Chromium, CSS applied
> import { injectAxe, checkA11y } from "axe-playwright";
> export default {
>   async preVisit(page) { await injectAxe(page); },
>   async postVisit(page) {
>     await checkA11y(page, "#storybook-root", {
>       detailedReport: true,
>       axeOptions: { runOnly: ["wcag2a", "wcag2aa", "wcag22aa"] },
>     });
>   },
> };
> ```
>
> ```yaml
> - run: npx playwright install --with-deps chromium
> - run: npm run build-storybook
> - run: npx concurrently -k -s first
>          "npx http-server storybook-static -p 6006 --silent"
>          "npx wait-on tcp:6006 && npm run test-storybook"
> ```
>
> Storybook's globals already generate the light/dark × comfortable/compact matrix, so one run
> covers all four with colours actually resolved. Zero serious or critical, as `00` §5.5 requires —
> and now the assertion means what it says.

```js
            [1, -0.0894841775, -1.291485548]];
const L2R = [[4.0767416621, -3.3077115913, 0.2309699292],
             [-1.2684380046, 2.6097574011, -0.3413193965],
             [-0.0041960863, -0.7034186147, 1.707614701]];
const lin = ([L, C, H]) => {
  const lab = [L, C * Math.cos(H * Math.PI / 180), C * Math.sin(H * Math.PI / 180)];
  const lms = M2.map(r => (r[0] * lab[0] + r[1] * lab[1] + r[2] * lab[2]) ** 3);
  return L2R.map(r => r[0] * lms[0] + r[1] * lms[1] + r[2] * lms[2]);
};
const inGamut = c => c.every(v => v >= -1e-4 && v <= 1 + 1e-4);
const clip = c => c.map(v => Math.min(1, Math.max(0, v)));
const lum = ([r, g, b]) => 0.2126 * r + 0.7152 * g + 0.0722 * b;
const ratio = (f, b) => { let [x, y] = [lum(f), lum(b)]; if (x < y) [x, y] = [y, x];
                          return (x + 0.05) / (y + 0.05); };

// agent-perimeter amber is fixed by 00 section 8 and asserted verbatim by the token test.
// It is 2.46:1 on paper and outside sRGB, so it is fill and field only -- never a
// meaning-bearing stroke, never text. That is what --bok-accent-ink is for; design
// section 8.5 records it. Anything NOT on this list failing is a real regression.
const RECORDED = new Set(["LIGHT --bok-accent-agent-perimeter"]);

const file = process.argv[2] ?? new URL("../src/tokens.css", import.meta.url);
const src = readFileSync(file, "utf8");
const cut = src.indexOf('[data-theme="dark"]');
if (cut < 0) throw new Error("no dark-theme block; tokens.css has moved");

// Deliberately no regex, and deliberately split on ";" rather than on lines: the dark
// block puts two declarations on one line, and a per-line parser silently drops the
// second -- which is every dark-mode -ink token, the whole half carrying the 4.5:1 text
// floor. The first draft of this file did exactly that: it reported "48 tokens measured"
// and stayed green with a dark ink dropped to 1.4:1. The count assertion below is what
// makes that visible rather than reassuring.
const parse = blk => {
  const out = {};
  for (const decl of blk.split(";")) {
    const at = decl.indexOf("--bok-"), ok = decl.indexOf("oklch(");
    if (at < 0 || ok < 0) continue;
    const name = decl.slice(at, decl.indexOf(":", at)).trim();
    const nums = decl.slice(ok + 6, decl.indexOf(")", ok)).split(" ")
                     .filter(Boolean).map(Number);
    if (nums.length === 3 && nums.every(n => !Number.isNaN(n))) out[name] = nums;
  }
  return out;
};
const R = parse(src.slice(src.indexOf(":root {"), cut)), D = parse(src.slice(cut));
// Both halves, counted. A gate that measures an empty set reports success.
if (Object.keys(R).length < 24 || Object.keys(D).length < 20)
  throw new Error("parsed " + Object.keys(R).length + " :root and " + Object.keys(D).length +
                  " dark tokens, expected at least 24 and 20 -- the parse has stopped matching");

const failures = [];
const semantic = n => ["critical", "high", "medium", "low", "info",
                       "verified", "modelled", "unverified", "accent-"].some(k => n.includes(k));
const check = (label, v) => {
  const need = label.endsWith("-ink") ? 4.5 : 3.0;      // text floor vs graphic floor
  const bg = label.startsWith("DARK") ? R["--bok-neutral-12"] : R["--bok-neutral-1"];
  const r = ratio(clip(lin(v)), clip(lin(bg)));
  const gamut = inGamut(lin(v)) ? "" : "   [outside sRGB, the browser will clip it]";
  if (r < need && !RECORDED.has(label))
    failures.push(label + "  " + r.toFixed(2) + ":1 < " + need + gamut);
};
for (const [n, v] of Object.entries(R))
  if (semantic(n) && n !== "--bok-accent") check("LIGHT " + n, v);
for (const [n, v] of Object.entries(D)) if (semantic(n)) check("DARK  " + n, v);
for (const i of [9, 10, 11, 12])                    // 1..8 are surfaces, not text
  check("LIGHT --bok-neutral-" + i, R["--bok-neutral-" + i]);

// The instrument itself, checked before its verdict is trusted. An approximate luminance
// transform is what let the R1 colour fixes ship believed-correct.
//
// Black-on-white alone is NOT sufficient: any coefficients summing to 1 reproduce 21.00,
// so flattening them to 0.3333 each passes it while every chromatic ratio goes wrong.
// The primaries are pinned individually, which is the assertion that actually bites.
const anchor = ratio(clip(lin([0, 0, 0])), clip(lin([1, 0, 0])));
if (Math.abs(anchor - 21) > 0.05)
  throw new Error("transform is wrong: black on white = " + anchor.toFixed(2) + ", must be 21.00");
for (const [name, rgb, want] of [["red", [1, 0, 0], 0.2126], ["green", [0, 1, 0], 0.7152],
                                 ["blue", [0, 0, 1], 0.0722]])
  if (Math.abs(lum(rgb) - want) > 1e-6)
    throw new Error("luminance coefficient for " + name + " is " + lum(rgb) + ", must be " + want);

if (failures.length) { for (const f of failures) console.error(f); process.exit(1); }
console.log("contrast OK -- " + (Object.keys(R).length + Object.keys(D).length) +
            " tokens measured, " + RECORDED.size + " recorded exception");
```

**Break it and watch it go red** — step 4d applies here, and all four of these were run
against the token block above before it was written down:

| Break | Expected |
|---|---|
| `--bok-medium` back to `oklch(0.72 0.13 78)` | `LIGHT --bok-medium  2.41:1 < 3` |
| any dark `-ink` dropped in lightness | `DARK  --bok-critical-ink  1.21:1 < 4.5` |
| rename the `--bok-` prefix | `parsed 0 :root and 0 dark tokens` |
| flatten the luminance coefficients to `0.3333` each | `luminance coefficient for red is 0.3333, must be 0.2126` |

The second one is the reason the parser splits on `;` and not on lines, and the reason the
token count is asserted. The first draft split on lines, and the dark block writes two
declarations per line — so it silently measured 48 of 56 tokens, dropped every dark `-ink`,
and stayed green with a dark ink at 1.21:1. It reported a number the whole time. That is the
R1 blackout counter again, in a file written specifically to avoid it.

The fourth is the same lesson about the instrument. Black-on-white was the only anchor at first,
and it does not discriminate: any three coefficients summing to 1 reproduce 21.00, so the flattened
transform passed the self-check while every chromatic ratio in the file was wrong. The primaries are
pinned individually now. A self-check that cannot fail is worth exactly as much as a test that
cannot fail, and it is harder to notice because it sits in the part of the file you trust.
